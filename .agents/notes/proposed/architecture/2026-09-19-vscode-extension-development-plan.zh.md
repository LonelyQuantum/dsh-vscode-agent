# Agent Note: 基于共享 DSH 应用开发 Codex 风格的 VS Code 扩展

Status: proposed

[English](2026-09-19-vscode-extension-development-plan.md) | 中文

## 问题

此 fork 需要一个以编辑器为中心、具有 Codex 风格交互的 VS Code 扩展，包含对话、显式文件和选区上下文、工具进度、审批及变更审查。ProleCoder 提供已有的交互参考。DSH 必须继续负责 agent（智能体）执行、会话及权限，让扩展可以跟随上游发展，无需维护平行实现。

维护独立的 alpha 和 RC 开发线，初始分别适配官方 `dsh-v0.2.1-alpha.2` 和 `dsh-v0.2.0-rc.2`。当前集成线为 RC；alpha 分支仍仅包含官方基线。`origin/feat/vscode-extension-foundation` 保留此前 `dsh-v0.1.7-rc.2` 实现，作为可恢复的移植来源。[VS Code 预览](../../../../apps/vscode/README.zh.md)已实现 P0–P4 的开发项。下方发行版适配及后续开发顺序规定剩余工作；历史验证不代表当前共享后端产物已通过验收。

## 提案

保留轻量的 VS Code Extension Host 和带编辑器专用布局的嵌入式 DSH Client。默认每个规范化 Harness 主目录只有一个共享 Desktop profile 后端，两端均可通过共享配置文件运行器启动它；隔离模式仅作为显式选择保留。DSH 负责提供方配置、凭据、对话、权限及执行。首先验证 Windows 本地工作区分发；其他操作系统和远程工作区需要独立里程碑。

### 长期开发分支 — 2026-10-10

保留两条插件开发线，让上游 API 适配可以在 RC 候选采用之前推进。RC 线从 alpha 线引入经过审查的插件改动，不引入其更新的 DSH 基线。RC 仍属于预发布标识，不能替代发行验收。

| 分支 | 初始官方基线 | 职责 |
|---|---|---|
| `develop/vscode-alpha` | [`dsh-v0.2.1-alpha.2`](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-alpha.2) | 基于最新已发布 alpha 标签适配新 API 并开发插件功能。 |
| `develop/vscode-rc` | [`dsh-v0.2.0-rc.2`](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.0-rc.2) | 保留最新已发布 RC 基线，验证筛选移植的功能，作为默认社区发行候选。 |
| `master` | 已拉取的 `upstream/master` | 镜像官方主线，不包含插件提交，不作为 RC 集成来源。 |

按用户要求先开发 RC，使 `develop/vscode-rc` 保持在 `dsh-v0.2.0-rc.2`。从保留的远端来源集成自有插件改动，不导入 alpha 基线。单独实施适配前，`develop/vscode-alpha` 保持在官方 alpha 标签；`master` 仅镜像上游。RC 检查通过后推送三个长期分支。两条插件线均验证通过前保留远端移植来源。

1. 获取官方标签并确认发布状态及渠道，再为各线选择后继版本。各线基于所选标签更新，不使用无标签的 `master` 顶端。没有新 RC 发布时，RC 基线保持不变，alpha 可继续前进。在各线适配证据中记录所选标签和实际包管理器/运行时要求。
2. 在 alpha 上以小而独立、经过测试的改动开发插件功能。将上游集成及生成式版本/依赖变化与可移植功能提交分开。RC 筛选包含所需功能依赖、测试及双语文档。
3. 使用 `git cherry-pick -x` 将适用的自有提交移植到 RC；直接回放不兼容时，使用 RC API 实现相同行为。不将整个 alpha 分支合并到 RC，也不整体复制其锁文件、生成目录或 DSH 版本。在 RC 重新验证结果；alpha 测试通过仅提供参考证据，不构成 RC 验收。缺少上游能力的功能延后，不静默提升 RC 基线。
4. 必要时先在 RC 修复紧急安全或阻塞问题，再记录来源并同步到 alpha。已发布的长期分支优先通过经过审查的集成分支向前合并更新；重写历史需要明确授权、保留原顶端及精确租约保护。上游 PR 仍使用基于官方 `master` 的独立分支。

两条线使用独立的临时 Harness 主目录及安装/产物目录。不让 alpha 和 RC 写入器共用同一主目录，也不将 alpha 写过的主目录用作 RC 降级测试。Desktop 共享仅在匹配的运行时/协议组合内验证。每个产物记录开发线、DSH 标签和校验值，任一线均不借用另一线的安装版验收。遵循[发布清单](../../../../apps/vscode/RELEASING.zh.md)，单独批准发行前，扩展开发版本保持 `0.0.1`。

### 基于发行版的适配 — 2026-10-10

官方默认分支为 `master`，不是 `main`。本日拉取的 `upstream/master`、本地 `master` 及最新已发布标签 [`dsh-v0.2.1-alpha.2`](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-alpha.2)指向同一提交。该版本于 2026-10-09 发布，属于预发布版，不是稳定版。拉取它并快进本地 `master` 不会将它集成到扩展分支。单独执行适配操作前，应保留已有未提交计划改动和功能分支历史。

即使官方 `master` 继续前进，alpha 适配仍固定此标签。相对 `dsh-v0.1.7-rc.2` 新增 1,383 个可达提交，Desktop 启动、运行时准备、Web 组合、Client 展示、Auto 审查、Windows 检查和生成目录均与本地改动重叠。按各自归属逐项解决，不以 fork 副本整体覆盖上游文件。结合标签源码及升级指南检查[发行说明](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-alpha.2)。

RC 目标于 2026-09-29 发布，相对旧基线新增 448 个可达提交。它固定 pnpm `11.7.0`，保留 `webRuntime` 信任配置及文本草稿持久化，不提供 alpha 的工作目录服务。它已包含实验性定时反问和默认开启的 Desktop 产品分析。共享启动/隐私、提供方首次配置及 Windows 验收在两条线均需完成；RC 所选发行版包含相应能力前，不引入 alpha 专属的目录、草稿及传输 API 变化。

已发布的官方 Desktop 不包含此 fork 的共享租约运行器。共享需要与匹配的适配版 Desktop 一起验证，仅 DSH 版本字符串相同不构成兼容证据。VSIX 独立使用不得依赖安装该 Desktop。

### RC 集成进度 — 2026-10-11

RC A0 已基于 `dsh-v0.2.0-rc.2` 实现；alpha A0 仍待完成。RC 保留登录 shell 环境准备，在任一冷启动路径传递所选客户端版本。新的社区 profile 在初始化前禁用产品分析；已有 profile 配置保持不变。隔离采集器验证尚未完成，因此 A1 仍为部分完成。

构建、扩展类型检查、完整 contract-ready lint、定向单元测试及无密钥编辑器上下文重放已通过。打包运行时的共享后端场景通过 Desktop 先启动、VS Code 先启动及并发启动验证，包含共享提供方配置/历史、密钥轮换、崩溃恢复及最后租约释放。Webview 上下文和工具卡检查已通过。GUI、文档及 hygiene 失败项已修复或定位为执行沙箱访问限制，对应检查复跑通过；未仅因提交或推送重跑完整聚合检查。

Windows x64 开发 VSIX 的扩展版本保持 `0.0.1`，在 `runtime.json` 记录 DSH `0.2.0-rc.2`、发行标签、分支及锁文件摘要。发行文件验证和校验值验证已通过。安装版编辑器 UX 尚未通过验收：VS Code 持有 `vscode-updating` 时，隔离窗口无法启动。推送开发分支不代表 A4/N4 完成，也不构成公开发布。A2–A4/N1–N4 保留下方验收标准。

### 后续开发顺序 — 2026-10-01

下一目标是让新用户无需安装或打开 Desktop，即可安装、配置并使用社区预览。保留现有会话列表和底部输入框设计。后端冷启动、共享数据归属、社区身份标注、隐私文档、打包检查及开发版本策略已经存在，不再作为新增功能里程碑。[共享后端归属](../../../../apps/shared-host/README.zh.md)、[编辑器 UX](../../../../packages/client/ui-vscode/README.zh.md)及[发布清单](../../../../apps/vscode/RELEASING.zh.md)分别定义其当前行为。

主要功能缺口是共享提供方首次配置：`dsh.configure` 可以选择已有主目录，或保存私有密钥并切换到隔离模式，但不能配置全新的共享主目录。当前编辑器测试仅允许 `--fresh-shared` 用于无密钥启动和 UX，拒绝共享模式与真实模型交互、故障、安全、信任及兼容性检查组合。因此，后端级证据和此前隔离模式编辑器检查不构成共享模式发行验收。最近一次安装版共享编辑器测试被编辑器更新互斥锁阻止；测试前应重新检查环境，不假定它仍然受阻。

### R4 安全决策

2026-09-28 的 `0.0.4` 安全收尾通过 162 项定向测试，Auto 的全部 35 项测试通过，入口模块的语句、分支、函数和行覆盖率均为 100%。无密钥浏览器检查覆盖录制的审批/拒绝及在线卸载；实际发布组合验证所属终端清理。Windows 源码和安装版检查覆盖 CSP、资源访问限制、进程归属、键盘/焦点、插件启停，以及 Auto 重启/卸载后的人工审批拒绝。启用 Developer Mode 并安装 PowerShell 7 后，workspace 和 Windows ACL 的 14 个文件、237 项测试全部通过。安装版 Auto 复验有一次在卸载审批器后等待 Read Only 时超时；加入观测的复跑通过，该间歇性失败仍未解决。此前仓库全量单元测试在出现失败和停滞后被终止；这些定向结果不代表全量套件已全绿。这些证据不构成其他平台的验收，也未消除下述样式属性例外。

Webview 禁止 `unsafe-eval` 和不带 nonce 的内联 style 元素。共享 Loader 延迟编译表达式，保留受信任 Host 的 `!!js` 语义；插件脚本和生成的样式继承页面 nonce。共享布局与数学公式渲染仍保留 `style-src-attr 'unsafe-inline'`。CSP 不会隔离已安装 Cordis 插件，也不替代工具权限；这些插件属于受信任代码。[Auto 安全卸载决策](../../implemented/bug-fix/2026-09-28-auto-review-safe-teardown.zh.md)在根上下文关闭时保留 Auto，运行中移除 reviewer 时将存活 Session 切换为 Read Only。运行中移除会取消 Auto 工作，并在降权前关闭其拥有的终端。旧 Full access 选择需要用户显式检查。

每个规范化 Harness 主目录使用一个由后端持有的上游写入锁。共享模式允许多个原生客户端通过租约连接该写入方；隔离模式保留私有工作区主目录的写入方。独立写入方共享同一主目录会带来会话及 profile 状态不一致的风险；为每个窗口分配新数据则会在每次重新打开时隐藏历史。规范化目录别名，并在后端资源释放结束前始终持有写入锁，防止原生客户端退出时过早允许第二个写入方进入。复用上游已退出持有者处理，不引入基于时间的抢锁或独立写入锁协议。

### 进程与数据归属

Webview 负责展示和临时编辑器 UI。Extension Host 负责 Workspace Trust、当前工作区绑定、进程监管、原生编辑器操作及凭据访问。DSH 负责 agent 状态、持久化输入、审批状态、模型选择及工具。隐藏的 Webview 可以释放 UI 资源，但不能静默取消活动轮次；工作区关闭、扩展退出及显式停止遵循明确的进程和任务生命周期。

宿主将 Webview `postMessage` 连接至范围受限的 Extension Host 桥接层及后端现有的带身份验证 HTTP/WebSocket 端点。共享模式获取原生客户端租约；隔离模式管理私有子进程。保留 Gateway 流分帧及 Connection 恢复机制，不新增业务消息。Webview 资源映射、CSP、cookie 和字节流需要各自验证；Electron 的自定义协议和请求头拦截 API 不是 VS Code API。

启动 token、身份验证 cookie 和模型提供方密钥不得进入页面 URL、Webview 状态或日志。代理请求仅能访问所持有的运行时及准许的路由。复用现有根路径 token 交换和浏览器信任检查；不能为连通 Webview 而弱化身份验证。原生操作使用限定在当前 Webview 和工作区内的类型化命令，并支持取消和资源释放。

开发和测试使用临时 Harness 主目录，包括共享模式场景；不修改用户真实 Desktop 配置或历史。共享模式由 DSH 持有凭据，显式隔离模式保留私有 SecretStorage 选项。Webview 永远不接收原始密钥。远程及跨平台共享尚未验证；共享产品数据不代表可选可执行载荷相同。

VS Code 组合包通过共享 system-prompt 注册表拥有模型可见的界面说明节，禁用独立 Web 界面说明、浏览器打开及 URL 打印。该节描述显式编辑器快照及原生只读审查，不暴露私有运行时 URL；组合后的提示词及工具 schema 由录制场景固定。

### P0 进展与待定事项

P0 的 Windows 扩展开发宿主曾启动真实的共享 profile 应用、加载 Web 客户端及插件资源、发出 API 请求、建立 Gateway WebSocket、挂载编辑器专用对话，并停止其管理的 Node 子进程。当时的重启冒烟检查重新挂载及旧进程退出；工具栏提供新建对话、History、SecretStorage 配置及上次会话恢复。这些控件属于历史证据，不是当前默认会话列表的 UX。源码开发和 Windows x64 VSIX 均要求外部兼容 Node。P0/P1 安装冒烟在仓库外执行；当前共享模式产物验收归属 N3–N4。

Webview 桥接将认证保留在 Extension Host，保持 Gateway 分帧。真实 Webview 检查覆盖模型完成和取消、二进制上传、文件下载字节、排队消息转 steering，以及运行时重启后的对话恢复。Windows 源码预览故障检查还覆盖空闲 Gateway 重连及 shell 工具运行期间终止运行时。插件事件通过 `eventsource` 库和带认证的 Fetch 传输，不使用指向 Webview 来源的原生连接；该库的解析和重试处理避免维护另一套 SSE 实现。无密钥编辑器检查验证了 Host 停用和启用会移除并重新挂载布局，而不替换 Webview。适配器测试覆盖流断开后重连与取消；当前活动轮次的证据记录在上方集成章节。共享 Loader 支持不使用 `unsafe-eval` 的纯字面值 Client 启动；下方安全决策记录仍保留的样式属性例外。尝试此部分实现时，以预览的[限制和启动步骤](https://github.com/LonelyQuantum/dsh-vscode-agent/blob/feat/vscode-extension-foundation/apps/vscode/README.md)为准。

### 交付顺序

P4 预览检查覆盖历史记录键盘焦点、明暗和高对比度模式的宿主颜色、Windows 运行时终止后的显式重启，以及已安装 VSIX 的启动。源码预览的 shell 工具崩溃检查观察到子进程退出、消息恢复且不重复运行工具，以及后续真实模型回复。诊断排除页面原始异常。打包将工作区依赖、必需的 peer 和 Client 注入依赖选入生产运行时，记录确切版本及锁文件摘要，并拒绝平台或版本不匹配。共享 Web 组合包含 Office 转换依赖，但不包含 Desktop 的 Electron/Python/skills 载荷，也不附带额外的 Node/pnpm 分发。其他工具类别、加固发行的 CSP 审查及 macOS/Linux 验证仍待完成。

P3 使用由 `ui-conversation` 定义、`ui-vscode` 提供、Chat 和交付视图消费的可选 `ConversationEditor` 服务。原生宿主校验文件准入；捕获 review 读取基于 `workspaceChanges.contents` 的固定认证路由，共用 recorder 的上限和生命周期。未挂载编辑器服务时，Web 和 Desktop 保留原有 Sidebar 导航。这是只读 review，不持久化历史捕获，也不提供回退。Windows 原生编辑器及后端测试覆盖确切版本、后续磁盘编辑、新建和删除、重命名、二进制和大小拒绝及过期。真实模型在只读权限下请求写入，“允许一次”放行后，改动卡片打开原生 diff，其中只读文档与捕获版本一致。同一流程回答 `ask_user_question` 选项，并等待模型完成。

### 复用与上游维护

Windows 预览已为 P0–P4 的各个开发领域提交实现，但不代表发行验收全部完成。不持久化的主题注册跟随编辑器配色；浏览器回放检查共享控件及 320/420 px 下的消息宽度。交付预览时保留上述待验证项目。

参考 ProleCoder 的 Workspace Trust、编辑器选区及诊断、进程恢复、原生 diff 导航和 VSIX 测试。agent 执行、RPC 业务方法、历史、压缩（compaction）和工具展示继续由 DSH 负责。直接复用代码前需要确定来源和许可；行为参考不依赖导入 ProleCoder 的实现。

本地 `master` 跟踪 `upstream/master`，不包含扩展提交。获取上游并快进 `master`；长期开发分支跟随各自所选发行标签，按上述规则移植改动。明确授权重写历史时，保留本地备份及已拉取的远端顶端；之后推送重写历史须使用精确的 `--force-with-lease`，禁止 `--force`。同步 fork 远端 `master` 或发布任一开发分支均为独立推送操作，获取上游或创建本地分支不代表已执行推送。

## 考虑过的替代方案

**把全新无端口 IPC 后端作为首个里程碑。** 这会增加流、精确 Fetch 路由、字节传输、模块服务及恢复机制的维护职责。上游共享 Web 包装提供了偏离更少的可用参考。仅当实测 VS Code 限制阻止共享 Web 路径，或明确产品需求禁止监听端口时重新考虑。

**原样嵌入完整三栏 Web 页面。** 这能加快传输验证，但会重复编辑器的文件和预览区域，并挤压窄侧栏中的对话。它可以作为临时诊断视图；产品在编辑器专用布局中组合 `conversation.content`。

**基于 SDK 或 ACP（Agent Client Protocol）。** [当前 TypeScript SDK 的限制](../../../../packages/sdk/client/README.zh.md#known-limitations-and-deferred-work) 仍包括无法中途取消及缺少服务端到客户端请求。这些协议适合各自消费方，但不能替代此扩展所需的现有交互式 GUI API。

**复制 ProleCoder 的完整前后端。** 这会产生平行的会话、提供方及工具状态实现，同时失去 DSH 客户端演进带来的收益。保留编辑器集成行为，并围绕当前 DSH 接口实现适配器。

## 验收标准

- 首个版本完成编辑器工作流：选择上下文、发送、观察工具、审批、取消或 steering、检查变更，以及重载后恢复会话。
- P0 记录传输及打包运行时证据；P1 在扩展可选功能或操作系统支持前交付 Windows VSIX。
- 通过真实组合测试运行时取消、隐藏视图行为、崩溃、重启、工作区关闭及扩展资源释放。启动失败及不可用历史具有可见的恢复或限制状态。
- 上下文及收件箱改动保留模型输入日志和已发布格式迁移规则。原生审查绝不把部分 hunks 或可变的当前文件呈现为捕获的完整版本。
- 验证遵循[测试政策](../../../../docs/testing.zh.md)及[快照归属](../../../../snapshots/AGENTS.md)：录制会话案例位于 `snapshots/`，其他预期输出靠近其所属测试，并增加 Extension Host/VSIX 测试。GUI PR 按 [GIF 工作流](../../../skills/record-browser-gif/SKILL.md)附带真实服务器和模型证据。
- 共享 UI 改动运行相关 GUI 和浏览器回放检查；文档配对、本地化、发布产物及受影响行为运行各自检查。持久的架构决策附带 Agent Note，而不是每项局部 UI 调整都新增记录。

## 风险

Webview CSP 和来源规则可能阻止直接复用 Electron 的资源及身份验证适配器。P0 必须测试普通 Fetch 消费方和延迟分片，而不仅是 Connection RPC。任何桥接层都必须限制缓冲，并在重连前等待取消流完全结束。

当前变更记录器仅在会话存活时保留摘要及捕获字节，并发的用户或外部编辑可能进入轮次工作区比较。这是审查证据，不是 agent 独占修改的归因，也不是安全的回滚事务。持久化审查及应用和撤销需要独立的冲突与持久化设计。

上游 API 和插件组合尚未稳定。[LogicalSession 提案](2026-09-06-logical-session-storage-rebuild.zh.md) 是拟议工作，不是实现依赖。使用当前 Remote 及投影 API，固定经过验证的基线，并在每个里程碑前重新评估上游。引用的 Desktop、启动、流、Factory 和展示决策仍具有独立价值；此 VS Code 提案不取代它们。
